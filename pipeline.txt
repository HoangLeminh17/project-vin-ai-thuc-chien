## Key Types

```ts
// Course structure
type Course = {
  id: string
  title: string
  chapters: Chapter[]
}
type Chapter = {
  title: string
  lessons: Lesson[]
  quiz: { topic: string; questions: QuizQuestion[] }
}
type Lesson = {
  title: string
  key_concept: string
  outline: string[]          // 4-8 bullet points (Stage 1 output)
  concept?: ConceptCard      // populated after Stage 2
}

// ConceptCard (active recall format)
type ConceptCard = {
  question: string
  answer: string
  detail?: string
  followUps: string[]
}

// Quiz
type QuizQuestion = {
  question: string
  options: string[]          // 4 options
  answer: number             // correct index 0-3
  explanation: string
  source_chunk_id?: string   // "ci-li" format — matches lessonMastery() lookup key
}

// SRS Progress
type ProgressMapEntry = {
  status: 'NEW' | 'LEARNING' | 'REVIEW'
  nextReviewDate: string
  lastReviewedAt?: string
  isDue: boolean
}
type ProgressMap = Record<string, ProgressMapEntry>   // key = cardId

// Card ID format: `${chapterIndex}-${lessonIndex}`

// Diagnostic status (generation context)
type DiagnosticStatus = 'idle' | 'loading' | 'done' | 'error'
```

## UI Structure — /course/[id]/page.tsx → CourseFlow

/course/[id]/page.tsx loads the SavedCourse and renders <CourseFlow />.

CourseFlow manages a View state machine:
  init              → loading guard (prevents flicker)
  diagnostic-intro  → DiagnosticIntro (first visit only; skipped via justGenerated_ flag)
  diagnostic-loading→ spinner while fetching quiz from /api/diagnostic-quiz
  diagnostic-quiz   → DiagnosticQuiz (10 questions, MCQ)
  course-tree       → CourseTree (chapter/lesson overview)
  lesson            → LessonView (study/edit for one lesson)

localStorage flags used by CourseFlow:
  justGenerated_{id}        — set after generation; consumed on first mount:
                              if diagnosticQuestions_{id} is cached → route directly to diagnostic-quiz
                              else → route to course-tree (skip diagnostic-intro)
  diagnosticDone_{id}       — set after quiz or skip; prevents re-trigger on subsequent visits
  diagnosticResults_{id}    — JSON of question results (used to color-code CourseTree nodes)
  diagnosticQuestions_{id}  — pre-cached quiz questions generated during course build;
                              consumed by CourseFlow on justGenerated_ path; removed from
                              localStorage once loaded into component state

CourseTree layout:
  Chapter list with expandable lessons
  Lesson nodes color-coded: red (due/failed) · amber (learning) · green (mastered) · grey (new)
  "Tiếp tục học →" button picks the earliest-due lesson

lessonMastery() priority order (CourseTree.tsx):
  1. SRS entry for this course: progressMap[`${ci}-${li}`].lastReviewedAt >= course.createdAt
     → returns 100 (REVIEW not due) | 30 (LEARNING) | 10 (due/Again)
  2. Diagnostic result: diagnosticState[`${ci}-${li}`] (0–100 score from quiz)
  3. null → grey "Chưa test"
  Note: SRS entries predating course.createdAt are ignored — prevents ghost data
        from deleted/replaced courses with matching "ci-li" card IDs.

LessonView:
  StudyMode — flashcard (question → reveal → 4 SRS ratings: Again/Hard/Good/Easy)
  EditMode  — card editor + AI chips

StudyMode advance() behavior:
  On rating: submit SRS, show toast, slide out
  After animation: if nextIdx >= total → call onExit() (exit study mode)
                   else → slide in next card
  (No wrap-around — finishes the deck and exits)

Rating meta (study mode):
  0 Again  — "không nhớ"  — 1 phút
  1 Hard   — "lờ mờ"      — 10 phút
  2 Good   — "nhớ rồi"    — 1 ngày
  3 Easy   — "quá dễ"     — 4 ngày
  Keyboard: phím 1-4; spacebar = xem đáp án

## Generation flow (app/page.tsx + generation-context.tsx)

Status machine: idle → parsing → generating → done

GenerationScreen is rendered while status === 'generating' || status === 'done'
  (keeps UI visible for cached fast-path courses; previously only shown for non-cached)

PipelineTracker shows 4 steps:
  1. Phân tích tài liệu       — done when status leaves 'parsing'
  2. Tạo cấu trúc khoá học   — done when course JSON resolves
  3. Tạo nội dung bài học     — done when all chapter content resolves
  4. Tạo bài test chẩn đoán  — driven by diagnosticStatus from generation context
     pending → active (loading) → done | error

diagnosticStatus: DiagnosticStatus
  Exported from generation-context; updated by runDiagnosticPrefetch().
  'idle'   — not started
  'loading'— POST /api/diagnostic-quiz in flight
  'done'   — questions saved to localStorage
  'error'  — fetch failed or empty response

Three generation paths in startGeneration():
  1. existing (contentHash match + API alive)  → set justGenerated_ + redirect
     also calls runDiagnosticPrefetch if: no cached questions AND diagnosticDone not set
     AND existing.courseContent exists
  2. fromCache + courseContent in response     → load map from cache, saveCourse, runDiagnosticPrefetch
  3. fromCache fallback (no content)           → parallel fetchChapter calls, saveCourse, runDiagnosticPrefetch
  4. fresh (not cached)                        → sequential fetchChapter, saveCourse per chapter,
                                                 runDiagnosticPrefetch after all chapters done

runDiagnosticPrefetch(courseId, markdown):
  Sets diagnosticStatus = 'loading'.
  POSTs markdown to /api/diagnostic-quiz.
  On success: stores questions in localStorage `diagnosticQuestions_{id}`, sets status = 'done'.
  On failure/empty: sets status = 'error'.
  (Replaces old fire-and-forget preFetchDiagnostic — now tracks status for UI feedback)

buildMarkdown(title, course, contentMap) / courseToMarkdown(course, courseContent):
  Lesson headings are prefixed with [ci-li] bracket notation, e.g.:
    ### [0-2] Tên bài học
  This allows the diagnostic AI to return source_chunk_id: "0-2" which matches
  the lessonMastery() and diagnosticState lookup keys in CourseTree.

Library refresh (app/page.tsx Home):
  Home tracks generation status via useRef(prevStatus).
  When status transitions from any non-idle state → 'idle', calls refreshCourses().
  Ensures the library shows newly generated courses without requiring a manual F5.
